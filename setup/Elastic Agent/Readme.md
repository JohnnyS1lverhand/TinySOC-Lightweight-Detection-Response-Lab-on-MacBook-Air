# Elastic Agent 9.0.0 (Linux ARM64)

**Elastic Agent** is a single, unified agent for logs, metrics, security data collection, and more, as part of the Elastic Stack. It supports automatic integration updates, centralized management via Fleet, and can run in both managed (Fleet) and standalone modes.

---

## Features

- **Collects logs, metrics, and security events** from servers, containers, and cloud environments
- **Works in Fleet (managed) or standalone (autonomous) mode**
- **Multiple integrations** (Filebeat, Metricbeat, Auditbeat, Endpoint Security, and more)
- **Centralized policy management and auto-updating**
- **Native support for ARM64 and x86_64 architectures**

---

## Installation (tarball for Linux ARM64)

### 1. Download and extract the archive

```
curl -L -O https://artifacts.elastic.co/downloads/beats/elastic-agent/elastic-agent-*-linux-arm64.tar.gz
```

```
tar xzvf elastic-agent-*-linux-arm64.tar.gz
```

```
cd elastic-agent-*-linux-arm64
```

---

### 2. Install and run Elastic Agent as a service

> **It is recommended to run the installation as root so the agent can collect all required data.**

```
sudo ./elastic-agent install
```
- By default, this installs the basic flavor of the agent.
- For the "server" flavor, use:  
```
sudo ./elastic-agent install --install-servers
```
---

### 3. Connect to Fleet (Kibana) or run in standalone mode

#### **Option 1: Managed mode (Fleet)**

1. In Kibana, go to **Fleet** and create a new enrollment token.
2. Enroll the agent with:

```
sudo ./elastic-agent install --url=<FLEET_URL> --enrollment-token=<ENROLLMENT_TOKEN> --non-interactive
```

- `<FLEET_URL>`: Fleet Server address (e.g., `https://kibana.example.com:8220`)
- `<ENROLLMENT_TOKEN>`: Your Fleet enrollment token

#### **Option 2: Standalone mode**

- Elastic Agent can run without Fleet by configuring local YAML files manually.
- For details, see the [Standalone Elastic Agent documentation](https://www.elastic.co/docs/reference/fleet/install-standalone-elastic-agent).

---

## Upgrading Elastic Agent

- To upgrade, download the new tarball, extract it, and run the install command again.
- In Fleet mode, upgrades can be managed centrally from Kibana.

---

## Uninstalling Elastic Agent

```
sudo ./elastic-agent uninstall
```

---

## Useful Commands

- **Check agent status:**

```
sudo elastic-agent status
```

- **View logs:**
```
sudo journalctl -u elastic-agent
```
or
```
less /opt/Elastic/Agent/data/elastic-agent-*/logs/elastic-agent.log
```

## Adding Integrations: Auditd, Suricata, ClamAV (Custom Logs)

After installing and enrolling Elastic Agent, you can easily add integrations for collecting logs from auditd, Suricata, and ClamAV.

1. **Go to Kibana → Fleet → Agent Policies.**
2. **Select the policy assigned to your Elastic Agent.**
3. **Click “Add integration”.**
4. **Search for and add the following integrations:**
    - **Auditd Logs** (collect logs from Linux audit daemon)
      Install with: [Auditd setup](AuditD)
    - **Suricata** (collect logs from Suricata IDS/IPS)
      Install with: [Suricata setup](Suricata)
    - **Custom Logs** (for ClamAV or other log sources; note: “Custom Logs” is marked as deprecated in recent Elastic versions, but still available)
      Install with: [ClamAV](ClamAV)
5. **For each integration:**
    - Specify the log file path (e.g., `/var/log/audit/audit.log` for auditd, Suricata log path, or your ClamAV log/script output).
    - Save and deploy changes.

You can now monitor logs and security events from all these sources in Kibana.

> **Tip:**  
> For ClamAV, if you use a custom script to export logs, point the Custom Logs integration to the output file generated by your script.
